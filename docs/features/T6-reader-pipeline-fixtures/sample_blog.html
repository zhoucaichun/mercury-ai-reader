Python 异步编程：从回调到 async/await

张三 2025年5月10日 Python 异步

1. 为什么需要异步编程？

在传统的同步编程模型中，当一个 I/O 操作（如网络请求、文件读写）发生时，程序会阻塞等待直到操作完成。这在处理大量并发请求时效率极低。

考虑这样一个场景：一个 Web 服务器需要同时处理 1000 个客户端连接。如果每个请求都需要 100ms 的数据库查询时间，同步方式下需要 100 秒才能全部完成——这显然无法接受。

"异步编程不是让单个操作变快，而是让等待时间不再被浪费。" —— 引自 Python 官方文档

2. 从回调地狱开始

最早的异步编程使用回调函数（Callback）。当一个异步操作完成时，调用预先注册的回调函数来处理结果。

import asyncio

def fetch_data(url, callback):
    # 模拟异步请求
    def on_response(response):
        data = response.json()
        callback(data)
    return on_response

# 嵌套回调 —— "回调地狱"
fetch_data("/api/user", lambda user:
    fetch_data(f"/api/posts/{user['id']}", lambda posts:
        fetch_data(f"/api/comments/{posts[0]['id']}", lambda comments:
            print(f"第一条评论: {comments[0]}")
        )
    )
)

这种方式很快就会陷入"回调地狱"：代码层层嵌套，错误处理困难，流程控制复杂。当业务逻辑稍复杂时，代码可读性急剧下降。

3. Future 和 Promise：让异步"可组合"

第二代方案引入了 Future 对象（在 JavaScript 中称为 Promise）。Future 代表一个"尚未完成的计算"，它提供了链式调用的能力，显著改善了代码结构。

Python 的 concurrent.futures 模块提供了基础的 Future 实现，但真正的异步飞跃来自 asyncio。

4. async/await：异步编程的语法革命

Python 3.5 引入了 async 和 await 关键字，让异步代码读起来像同步代码。这是 Python 异步编程的分水岭。

4.1 核心概念

  • 协程（Coroutine）：用 async def 定义的函数，可以在执行中暂停和恢复
  • 事件循环（Event Loop）：调度和执行所有协程的引擎
  • 可等待对象（Awaitable）：可以被 await 的对象（协程、Task、Future）

4.2 实际示例：并发 HTTP 请求

import asyncio
import aiohttp

async def fetch_url(session, url):
    async with session.get(url) as response:
        return await response.text()

async def fetch_all(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_url(session, url) for url in urls]
        return await asyncio.gather(*tasks)

# 使用
urls = [
    "https://api.example.com/data/1",
    "https://api.example.com/data/2",
    "https://api.example.com/data/3",
]
results = asyncio.run(fetch_all(urls))
print(f"并发获取了 {len(results)} 个结果")

以上代码并发发起三个 HTTP 请求，总耗时约等于最慢的那个请求，而非三者之和。

5. 实际性能对比

方案 100 个请求耗时 CPU 占用 代码复杂度
同步 + 多线程 12.3 秒 高 中（需处理锁）
回调式异步 3.1 秒 低 高（回调地狱）
async/await 2.8 秒 极低 低（像同步代码）

6. 常见陷阱与最佳实践

  1. 不要在协程中调用阻塞函数

    阻塞函数（如 time.sleep()）会卡住整个事件循环。请使用 await asyncio.sleep() 或在线程池中执行。

  2. 避免创建过多协程

    虽然协程很轻量（KB 级别内存），但上万个协程同时运行仍可能带来调度开销。使用 asyncio.Semaphore 限制并发数。

  3. 正确处理异常

    asyncio.gather() 默认会在第一个异常处停止。使用 return_exceptions=True 可以让所有协程执行完毕后再统一处理异常。

7. 总结

Python 异步编程从回调、到 Future、再到 async/await，经历了十多年的演进。如今的 asyncio 生态已经非常成熟，是构建高性能 I/O 密集型应用的首选方案。

核心要点：

  • async/await 让异步代码"看起来同步"
  • 事件循环是异步的心脏，不要阻塞它
  • asyncio 官方文档是最好的学习资源
